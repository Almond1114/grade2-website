# 2Base 2年3組版：接続と更新

写真は「お知らせ」への添付と、2年3組ページの「時間割の写真」に使えます。お知らせの写真はホーム・2年3組ページ・お知らせ一覧に表示します。時間割の写真は掲載日が新しい登録画像を1枚表示し、元のClassroom投稿も開けます。

GitHubにコードを反映する操作と、Google側でApps Scriptを更新する操作の両方が必要です。既存のGAS_URL・SHEET_URL・Firebase設定は保持しています。Google側の設定と本番での写真保存は、まだ実行・確認していません。

## 1. 既存のApps Scriptを開く

`app-config.js` の `SHEET_URL` にあるスプレッドシートを開き、「拡張機能 → Apps Script」に進みます。今使っているWebアプリと同じプロジェクトを更新してください。

1. リポジトリの [Code.gs](../Code.gs) で既存の `Code.gs` を更新します。
2. Apps Script左側の「＋ → スクリプト」で `Media` を追加し、[Media.gs](../Media.gs) を貼ります。
3. 「プロジェクトの設定 → appsscript.jsonマニフェスト ファイルをエディタで表示する」を有効にします。
4. [appsscript.json](../appsscript.json) のClassroomサービスと `oauthScopes` を反映します。すでに他のサービスや設定がある場合はそれを保持して、必要な項目を追加してください。

Google Classroom APIは、左側「サービス → ＋ → Google Classroom API → 追加」からも設定できます。標準Google Cloudプロジェクトを関連付けている場合は、そちらでもGoogle Classroom APIを有効にしてください。

## 2. 写真を保存するフォルダを決める

Driveに2年3組用の保存先フォルダを用意し、閲覧するメンバーに閲覧権限を設定します。Webアプリをデプロイするアカウントが、このフォルダにファイルを作れる必要があります。

フォルダURLが `https://drive.google.com/drive/folders/ABCDEFGHIJK` なら、フォルダIDは `ABCDEFGHIJK` です。

アップロードしたファイルはこのフォルダに作られ、フォルダの共有範囲を引き継ぎます。Classroomから引用する写真はコピーせず、元ファイルを参照します。

## 3. スクリプト プロパティを設定する

Apps Scriptの「プロジェクトの設定 → スクリプト プロパティ」に設定します。

| 名前 | 入力する値 | 必要なとき |
| --- | --- | --- |
| `EDITOR_KEY` | 推測されにくい16文字以上の編集キー。例示の文字列を使い回さず、自分で決める | 保存・写真操作に必須 |
| `PHOTO_FOLDER_ID` | 手順2のフォルダID | Driveへのアップロードに必須 |
| `CLASSROOM_COURSE_IDS` | 2年3組のコースID。複数ある場合はカンマ区切り | Classroomの写真一覧を使うとき |
| `SPREADSHEET_ID` | 現在使用しているスプレッドシートのID。`app-config.js` の `SHEET_URL` 内の `/d/` と `/edit` の間の文字列 | 必須。接続先IDを公開サーバーコードに書かず設定する |
| `ALLOW_PUBLIC_PHOTOS` | `true` | 管理者が「リンクを知っている全員」の共有方法を選択肢に出す場合のみ |

`EDITOR_KEY` はGitHubのファイルや `app-config.js` に書かないでください。編集画面で入力したキーはページ内のメモリにのみ保持され、ページを閉じると消えます。

確認後はボタンが「編集を終了する」に変わります。押すとキーを破棄してロックします。別のページへ移動したときもキーを破棄するため、ブラウザの「戻る」で編集画面に戻った場合は再入力してください。編集を有効にしても、入力済みの本文・選択済みの写真はそのまま保持します。

`ALLOW_PUBLIC_PHOTOS` の既定値は無効です。有効にした場合も、編集者が写真ごとに共有用チェックを入れたときだけ、その新規写真をリンク共有に変更します。Classroomの元ファイルの権限は変更しません。

ClassroomのコースIDが不明な場合は、Classroomサービスを追加した後、Apps Script上で `listMyClassroomCourseIds` を実行します。実行ログに参加中のコースの名前とIDが表示されるので、2年3組の対象コースだけを `CLASSROOM_COURSE_IDS` に登録してください。Classroom画面のURL中の文字列と、APIのコースIDが異なる場合があります。

## 4. データを保持して移行し、権限を承認する

1. Apps Script上で `migrateGrade23` を1回実行します。必要なシート・不足している列だけを作り、既存の行は消しません。「時間割の写真」シートもこの手順で追加します。以前の写真機能から更新する場合も実行してください。
2. `authorizeGrade23` を実行し、Googleの権限確認を承認します。
3. フォルダ・Classroomコース・スプレッドシートを、デプロイするアカウントが開けることを確認します。

**既存サイトでは `setupSheets` を使いません。** 現行版では既存シートが見つかると初期化を拒否します。`migrateGrade23` は他クラスの古い行も削除せず保持し、APIと画面の表示対象から除外します。「全体」の既存行は学年共通の連絡として表示します。

初めての空のシートにサンプルを入れたい場合のみ `setupSheets` が使えます。サンプルは実際の授業予定ではありません。

## 5. 既存のWebアプリを新バージョンに更新する

1. 「デプロイ → デプロイを管理」で、今使っているWebアプリの鉛筆マークを押します。
2. バージョンを「新バージョン」にしてデプロイします。
3. 既存と同様に「次のユーザーとして実行：自分」を使います。
4. GitHub Pagesからの現在のアクセス方法を保つ場合、「アクセスできるユーザー：全員」を使います。学校側が外部Webアプリや外部共有を制限している場合は、その管理ポリシー内で設定してください。
5. 同じデプロイを更新すれば `GAS_URL` の変更は不要です。別のデプロイを作った場合は `app-config.js` のURLも更新します。

新しい編集画面はキー付きPOSTを使います。新しいApps Scriptは従来のキーなしGETによる編集を受け付けないので、Google側とGitHub側を続けて更新してください。写真を `no-cors` で送りっぱなしにせず、返ってきた成功結果を確認してから掲載します。

## 6. 写真を掲載する

### 端末の写真

1. 2Baseの「編集」を開き、編集キーを入力して「編集を有効にする」を押します。
2. 「お知らせを追加」を押し、タイトル・本文を入力します。
3. 「写真を添付 → 端末からアップロード」で写真を選びます。
4. 送信前のプレビューを確認し、「選んだ写真をDriveに保存」を押します。選び直す場合は「選択を解除」でフォームの画像URLを保ったまま選択を取り消せます。
5. プレビューと「画像URL」が更新されたことを確認し、最後に「保存する」を押します。
6. お知らせ一覧から、写真つきの連絡を確認します。

端末の写真は長辺2000px以下、3MB以下のJPEGに変換します。変換によって位置情報などの画像メタデータも引き継ぎません。元の写真が25MBを超える場合や、ブラウザがHEIC等を読み込めない場合は、小さなJPEG・PNGに変換して選び直してください。透過画像は白背景のJPEGになります。

### Classroomの写真

1. お知らせのフォームで「Classroomから引用」を選びます。
2. 「Classroomの写真を読み込む」を押して、登録済みのコースを取得します。
3. コースと投稿の種類（ストリームのお知らせ／課題／資料）を選び、再び読み込みます。
4. 写真の名前・投稿名を確認します。「元の写真を確認」で実物も開けます。
5. 「この写真を引用」を押すと、画像URLと、元のClassroom投稿へのリンクURLが入力されます。
6. お知らせの内容を確認して保存します。

写真がない投稿もあるため、20件の投稿ずつ確認します。「次の20件の投稿を確認」で続きが読めます。コースや投稿の種類を変えると、前の結果とページ位置をリセットします。PDFやGoogleドキュメントは写真一覧から省きます。提出された解答・成績・生徒名簿は取得しません。

### Classroomの時間割を表示する

1. 2年3組ページの「時間割の写真 → 写真を登録・更新」、または編集画面の「時間割の写真を追加」を開きます。
2. 編集キーを確認し、「Classroomの写真を読み込む」を押します。別のコースや「資料」にある場合は、コース・投稿の種類を選び直して再度読み込みます。
3. 初期の検索語は「時間割」です。読み込んだ添付画像の名前・投稿名から「時間割」「時間わり」「週予定」「週案」「週間予定」「日課表」を候補にします。検索欄を空にすると全件確認できます。空白で区切った複数語の検索も使えます。
4. 元の写真を確認し、「この写真を引用」を押します。画像URL・引用元リンクと、空欄の場合は投稿名からタイトルが入ります。
5. 掲載日・タイトル・必要なメモを確認し、「保存する」を押します。
6. 2年3組ページの「時間割の写真」に表示された画像と出典を確認します。

表示が有効な2年3組の行のうち、掲載日が新しい写真を表示します。同じ掲載日ならシートの後ろの行を優先します。以前の画像を消す必要はなく、「表示」をFALSEにすると次の画像に戻せます。URLが空の行や、形式の正しくないDrive URLは候補から除きます。

対象は投稿に添付された画像ファイルです。検索は名前・投稿名を対象にしており、画像内の文字を読み取って時間割表へ転記する機能や、Classroomの新規投稿を自動で反映する機能はありません。曜日ごとの文字の時間割と「明日の準備」は、引き続き「時間割」シートのデータを使います。

## 編集途中の内容

本文などの入力と未送信の写真は、種類・行を切り替えても同じページ内で下書きとして保持します。「元に戻す」で現在の行の下書きだけを破棄します。下書きはページ内メモリのみで、ページを閉じる・再読み込みする前に保存してください。ブラウザが対応している場合は未保存のまま離れると確認が出ますが、端末によっては表示されません。

写真を選んだ後は、先に「選んだ写真をDriveに保存」を押す必要があります。未送信の写真が残っている間は本文の保存を止め、操作を案内します。Driveへの保存とサイトへの掲載は別の操作です。

保存の成功応答を受け取った後に一覧の再読み込みだけが失敗した場合は、「保存しました」と「再読み込みは未完了」を分けて表示し、確認済みの保存内容をフォームに残します。通信が戻ったら「再同期」で最新一覧を確認してください。表示データの再同期に失敗した場合も、直前に取得できたデータと取得時刻を保ちます。

## 写真が表示されないとき

Driveの共有URLは画像そのもののURLではないため、`img` に直接渡さずDriveのプレビューを埋め込みます。下に「Driveで写真を開く」リンクも表示します。外部の通常の画像URLには通常の画像表示を使います。

閲覧者に元ファイルの権限がない場合、埋め込みのログインが制限されている場合、Safari等でGoogleのログイン情報を使えない場合は、Driveへのリンクから、権限のある学校アカウントで開いてください。Classroomのコース参加とDriveのファイル閲覧権限はそれぞれ確認が必要です。

「2年3組専用」は表示・保存対象を2年3組に固定する意味です。公開GitHub PagesのHTMLや公開データAPI自体は、学籍による閲覧制限ではありません。写真はDriveの権限で制限し、Classroom APIの一覧は編集キーとコースの許可リストで保護します。

## 保存に失敗したとき

- 「編集キーが正しくありません」：Google側の `EDITOR_KEY` と入力を確認します。
- 「旧版」「権限承認が未完了」：`Media.gs`、マニフェスト、権限承認、新バージョンへの再デプロイを確認します。
- 「通信できません」：WebアプリURLと公開アクセス設定を確認します。タイムアウトは保存済みの場合もあるので、一覧・保存先Driveを確認してから再送します。
- 「Classroomを取得できません」：デプロイしたGoogleアカウントのコース参加・API有効化・スクリプト権限を確認します。
- 「写真の共有設定を保存できません」：学校のリンク共有制限を確認するか、通常のフォルダの共有範囲を引き継ぐ方法を使います。

同じページから同じ内容を再送すると同じリクエストIDを使い、サーバーのキャッシュが残っている間は二重作成を抑えます。CacheServiceは永続台帳ではないため、ページを開き直した後やキャッシュが失われた後の再送まで重複を保証するものではありません。

「写真を外す」は、フォームから写真の参照を外す操作です。Driveの元ファイルは残ります。アップロード後にフォームを保存しなかった場合も、写真はDriveに残ります。Classroomから自動で付けた出典は写真を外す・端末の写真に差し替えると解除しますが、編集者が別のリンクへ書き換えた場合は保持します。

## 検証

`npm test` はApps ScriptのSheets・Drive・Classroomとフォーム・写真処理の境界をテスト用に置き換え、クラス固定、キー確認、共有範囲、引用元、再送、移行時のデータ保持、時間割画像の選択、下書き保持、保存後の通信失敗、URL処理、静的ファイルの参照を検証します。実際のGoogleへのアップロードや、学校アカウントでの閲覧の代わりにはなりません。

`npm run build` は外部依存なしで `dist/` を生成します。GitHub Pagesの既存のルート配信は継続できます。今回の作業環境ではプレビュー基盤の起動が失敗したため、実ブラウザでの見た目・端末別操作は未確認です。
